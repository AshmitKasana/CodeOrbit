# Code Orbit

**Explore. Learn. Master.** A free, AI-powered Data Structures & Algorithms learning platform. Ask any
programming or DSA question in plain English and get a structured, textbook-style lesson — then *watch*
the algorithms run in interactive labs.

🔗 **Live:** [codeorbit21.netlify.app](https://codeorbit21.netlify.app)

## Features

**Learn**
- **AI lessons on any topic** — overview, core concept, syntax, memory model, runnable examples, complexity,
  cross-language comparison, common mistakes, interview questions and practice problems, adapted to four
  levels (Beginner → Interview). Generated by Claude through a schema-validated backend.
- **Follow-up tutor chat** on every lesson, with the lesson as context.
- **Practice** and **Interview prep** pages, a **roadmap**, bookmarks, history and a ⌘K **command palette**.
- An in-browser **code playground** (Monaco) that runs JavaScript/TypeScript.

**Interactive labs** (run entirely in the browser — never use AI quota)
- **Algorithm Visualizer** — step through bubble, selection, insertion, merge, quick and heap sort, or **race
  two algorithms on the same data**; binary vs. linear search with the search window shown. Pause, step
  backwards, scrub the timeline, change the input shape (random / nearly sorted / reversed / few unique).
- **Big-O Explorer** — interactive growth-curve chart (log/linear), a live "how long would this really take?"
  table driven by an input-size slider, and a data-structure complexity cheat sheet.

**Progress**
- Daily **streaks**, **XP & levels** and **badges**, shown on the dashboard.

**Accounts**
- Supabase Auth: email/password, Google, Apple and GitHub sign-in. See [`AUTH_SETUP.md`](AUTH_SETUP.md).

## Quick start

```bash
npm install
npm run dev
```

Open http://localhost:5173. **No API key is needed** — without a backend the app runs on built-in offline
content (lessons are labelled "Built-in demo content" so it's always clear what you're looking at). The
interactive labs, roadmap, dashboard and playground work fully offline.

### Turn on real AI lessons

```bash
cp .env.example .env        # then set ANTHROPIC_API_KEY and VITE_USE_REAL_AI=true
npm run server              # backend on http://localhost:8787
npm run dev                 # frontend; Vite proxies /api/* to the backend
```

If the backend is unreachable or has no key, the frontend silently falls back to the built-in content.

| Script | What it does |
| --- | --- |
| `npm run dev` | Vite dev server |
| `npm run server` | Express backend (`server/index.js`) |
| `npm test` | Run all unit tests once (`npm run test:watch` to watch) |
| `npm run build` | Production build to `dist/` |
| `npm run preview` | Serve the production build |

## Architecture

```
Browser (React + Vite + Tailwind)                 Backend (Express, Node ≥ 20)
┌───────────────────────────────┐                ┌────────────────────────────────────────┐
│ pages/  Learn, Practice, ...  │  POST /api/... │ app.js   routes, validation, CORS      │
│ services/aiService.js         ├───────────────►│ lib/auth.js    who is calling?         │
│   • backend call + fallback   │                │ lib/quota.js   daily limits (server!)  │
│   • local content generator   │◄───────────────┤ lib/cache.js   LRU+TTL lesson cache    │
│ lib/algorithms, complexity,   │  lesson JSON   │ lib/ai.js      Claude + JSON schema    │
│   progress   (pure, tested)   │                └───────────────┬────────────────────────┘
└───────────────────────────────┘                                │ Anthropic SDK
                Supabase Auth  ◄── verifies tokens ──────────────┘   + optional Supabase quota table
```

**Key design decisions**

- **Structured outputs.** The model's response is constrained to a JSON schema (zod → `output_config.format`),
  so a lesson can never come back malformed or with a section missing. `server/lib/ai.js` then maps it to the
  shape the UI renders — the components never parse free text.
- **The daily limit is enforced on the server**, keyed by a verified Supabase user id (or a salted hash of the
  IP for anonymous visitors) — not by a counter in `localStorage` that anyone can reset. Signed-in users get a
  higher allowance. Cached lessons cost nothing and don't count. If an AI call fails, the unit is refunded.
- **The free endpoint can't become a general chatbot.** The learner's text is treated as data (wrapped in
  `<query>` tags, with instructions to ignore embedded commands), input length is capped, and the model flags
  non-CS requests (`OFF_TOPIC`), which are rejected and refunded.
- **Graceful degradation everywhere.** No API key → 503 → local content. No Supabase service key → in-memory
  quotas. Supabase SQL not installed → in-memory fallback (never silently unlimited).
- **Secrets stay server-side.** The Anthropic key and the Supabase `service_role` key are only ever read by
  `server/index.js`; the browser only ever talks to `/api/*`.
- **The visualizer can't disagree with the algorithm.** Each algorithm runs once and records a snapshot per
  operation; the UI just plays snapshots back. The generators are plain functions, unit-tested against
  `Array.prototype.sort`.

### API

| Route | Body | Response |
| --- | --- | --- |
| `POST /api/generate` | `{ query, level?, focus? }` — `focus`: `lesson` \| `practice` \| `interview` | `{ lesson, cached, quota }` |
| `POST /api/followup` | `{ topic, question, summary?, level?, history? }` | `{ answer, quota }` |
| `GET /api/quota` | — | `{ signedIn, generate, chat }` (each `{ used, limit, remaining, resetsAt }`) |
| `GET /api/health` | — | `{ ok, ai, model, quota }` |

Errors are JSON `{ code, error }` — `QUOTA_EXCEEDED` (429), `RATE_LIMITED` (429), `OFF_TOPIC` / `REFUSED`
(422), `AI_NOT_CONFIGURED` (503), `AI_BUSY` (503), `BAD_REQUEST` (400).

### Backend configuration

All optional — see [`.env.example`](.env.example) for the full list.

| Variable | Purpose |
| --- | --- |
| `ANTHROPIC_API_KEY` | Enables real AI. |
| `ANTHROPIC_MODEL` | Default `claude-opus-5`; use `claude-sonnet-5` / `claude-haiku-4-5` for lower cost. |
| `AI_EFFORT` | `low` (default) … `max`. Lower is faster and cheaper. |
| `QUOTA_GENERATE_ANON` / `_USER`, `QUOTA_CHAT_ANON` / `_USER` | Daily allowances (default 5 / 25 lessons, 10 / 50 follow-ups). |
| `SUPABASE_SERVICE_ROLE_KEY` | Verifies signed-in users and stores quotas durably. Run [`supabase/ai_usage.sql`](supabase/ai_usage.sql) once. |
| `CORS_ORIGIN`, `TRUST_PROXY` | Needed when the API is hosted on a different domain / behind a proxy. |

## Project structure

```
src/
├── components/        Reusable UI (CodeBlock, Diagram, LimitReached, QuotaBadge, ...)
│   ├── visualizer/    BarChart, PlaybackControls, SortingLab, SearchLab
│   └── glass/         The "Liquid Glass" surface system — navbar, modals, tooltips
├── pages/             Route-level pages (Home, Learn, Visualizer, Complexity, Dashboard, ...)
├── lib/               Pure, unit-tested logic: algorithms/{sorting,searching}, complexity, progress
├── services/          aiService (backend + offline fallback), quotaStore, authService
├── hooks/             useTopic, usePlayback, useQuota, useAuth, ...
└── utils/             constants, helpers (localStorage, query parsing)
server/
├── app.js             Express app factory (routes, validation, quota flow)
├── index.js           Entry point — wires the real Anthropic / Supabase clients
└── lib/               ai, quota, cache, burst, auth
supabase/ai_usage.sql  Optional durable quota table + atomic functions
.github/workflows/     CI: tests + production build on Node 20 and 22
```

Every route in `src/App.jsx` except `/` is lazy-loaded; Monaco and the visualizers only load when visited.

## Testing

```bash
npm test
```

~450 tests, run on every push by GitHub Actions:

- **Algorithms** — every sorting algorithm is checked against `Array.sort` on empty, single, sorted, reversed,
  duplicate and random inputs; binary search is checked for correctness and the `log₂ n` comparison bound.
- **Progress** — streak logic across month/DST boundaries, XP, levels and badges.
- **Server** — quota limits and refunds, caching, validation, CORS, error mapping, and the AI layer against a
  fake Anthropic client (including refusals, truncation and off-topic handling).
- **Frontend** — the AI service's backend/fallback behaviour and every new page rendering with its key content.
- A guard test that fails if paid-plan code is ever reintroduced.

## Deployment

The frontend is a static site; the backend is an optional small Node service.

1. **Frontend (Netlify — current host).** [`netlify.toml`](netlify.toml) sets the build, SPA fallback and security
   headers. Set `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and — if you host the backend — `VITE_USE_REAL_AI=true`
   and `VITE_API_URL=https://your-backend`.
2. **Backend (Render / Railway / Fly / any Node host).** `npm ci && npm run server`. Set `ANTHROPIC_API_KEY`,
   `CORS_ORIGIN=https://your-frontend`, `TRUST_PROXY=1`, and optionally `SUPABASE_SERVICE_ROLE_KEY`.
   Generating a full lesson can take a while, so use a host without a short serverless timeout.
3. **SEO.** [`public/robots.txt`](public/robots.txt) and [`public/sitemap.xml`](public/sitemap.xml); `index.html` carries
   Open Graph tags and JSON-LD. If you use your own domain, update the hard-coded `https://codeorbit21.netlify.app`
   URLs in those files and the `og:url` / `canonical` tags.

> The playground only *executes* JavaScript/TypeScript, sandboxed to the viewer's own browser tab. Running other
> languages safely needs a containerised backend runner, which is intentionally not included.

## Design language

Restrained, monochrome and dark-first, with exactly one reserved accent (`signal`, a muted blue). Liquid-glass
floating surfaces, a cursor-following spotlight, a ⌘K command palette, and animations that all respect
`prefers-reduced-motion`.
